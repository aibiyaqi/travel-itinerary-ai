# 安全与隐私说明

> 这份文档说明“已经做了什么”和“还没做什么”，避免把演示项目说成合规系统。

## 1. 仓库层：防止密钥与个人信息进入 Git

| 措施 | 实现 |
|---|---|
| 忽略本地密钥 | `.gitignore` 忽略 `.env`、`.secrets/`、`*.db`、`chroma_db/`、`exports/`、`data/uploads/` |
| 忽略个人资料 | 简历、面试笔记、口述文档、历史数据文件不纳入仓库 |
| 提交白名单 | 发布脚本只添加 `src/`、`tests/`、模板、Docker/CI/文档等明确目录 |
| 敏感信息扫描 | [`scripts/check_secrets.py`](../scripts/check_secrets.py)：API Key、GitHub Token、私钥、默认口令、手机号；CI 中作为门禁 |
| 提交身份 | 使用 GitHub noreply 邮箱，不暴露真实邮箱 |
| 示例脱敏 | 客户版 HTML 示例中的客户名已替换为“示例客户” |

当前公开仓库中**没有**：`.env`、业务数据库、Chroma 向量库、导出文件、客户手机号、个人简历/面试资料。

## 2. 运行层：已有的安全措施

- 密码使用 bcrypt 哈希，数据库中不存明文；
- 登录 Token 由 `secrets.token_urlsafe(32)` 生成，12 小时过期，登录即轮换，改密吊销；
- 方案详情/修改/导出有归属校验：顾问只能访问自己的方案，管理员不受限；
- 登录失败、生成、修改、状态变更、导出、建号、上传写入 `audit_logs`；
- API Key 只从环境变量读取，不写入日志；LLM 调用日志只记录 token 用量与估算成本；
- 审计写入失败不会阻断业务，也不会把异常内容打到前端；
- 导出 HTML 不包含 `internal_notes`（顾问内部备注）。

## 3. 还没做的（上线前必须补）

1. **数据库加密**：`biz_data.db` 是明文 SQLite，客户姓名、手机号未做字段加密；
2. **手机号脱敏**：列表/导出中默认展示完整号码，没有 `138****8000` 这类掩码；
3. **导出文件清理**：`exports/` 下的客户版文件不会自动删除，也没有保留期；
4. **数据保留/删除**：没有“客户要求删除”的流程与级联清理；
5. **Token 传输**：仍通过 URL 查询参数传递（已缩短到 12 小时、Nginx 日志剔除查询串），彻底方案是 Cookie/SSO；
6. **审计粒度**：只记录动作，不记录字段级 diff；`detail` 是自由文本，可能包含业务信息；
7. **登录限流**：没有失败次数锁定；
8. **备份加密**：`biz-db` 卷的备份脚本未加密。

## 4. 密钥与事故处理

- `.env` 中的 `QWEN_API_KEY` 一旦出现在聊天、日志、截图中，**立即到 DashScope 控制台吊销并重建**；
- 不要把 PAT / OAuth Token 写进代码、README、Issue 或提交信息；
- 如果误提交了密钥：先吊销，再清理 Git 历史（`git filter-repo`），仅删除文件不够；
- 生产环境建议用云厂商 KMS/Secrets Manager 注入，而不是把 `.env` 放在服务器磁盘上。

## 5. 面试口径

可以说：

> 仓库层用白名单 + 敏感信息扫描 + noreply 提交，保证密钥和客户数据不进公开仓库；运行层做了 bcrypt、Token 轮换、越权校验和审计。  
> 但数据库加密、手机号脱敏、数据保留策略还没做，这些是上线前要补的，不是已经完成的。

不要声称“已符合等保/GDPR”——当前只是开发阶段的基线防护。
